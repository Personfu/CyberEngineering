## Our review

Choose the 500 for a simple fixed learning station when microSD is sufficient and the higher-memory/storage package is unnecessary. Both 500 models share the documented Cortex-A76 processor family, so the useful distinction is memory, storage and input rather than pretending the Plus is a completely different CPU platform. A keyboard computer can make a tidy engineering station, but count the monitor, power supply and pointing device in the complete setup. We favor this format over a tiny cyberdeck for sustained coding and reading logs.

## Choose it when

You need a fixed Linux bench with a full-size typing surface.

## Skip it when

You primarily need field portability, an integrated display or x86-only tools.

## Compatibility and limitations

The 500 and 500+ are separate configurations. SSD replacement and mechanical-key customization are documented for the Plus; do not assume them on the standard 500. Neither is an integrated screen/battery handheld. Package contents vary between a standalone unit and a kit.

## Alternatives

HackberryPi CM5 or uConsole for handheld work; a conventional laptop for an integrated display and battery.

## Setup and firmware route

Use the [model-appropriate installation and recovery guide](../../labs/guides/linux-cyberdeck.md) and the [firmware route index](../../labs/FLASHING.md). Record model/revision, current firmware, required peripherals, artifact source and digest before a write. Preserve configuration and establish the vendor recovery route first.

The [benchkit helper](../../labs/SCRIPTS.md) can record inventory, verify artifact bytes and prepare an explicit dry-run flash plan. A successful boot is only a prerequisite: verify the actual function you need.

## First evaluation

Verify the exact kit and storage device, then run a representative local build with the intended monitor and power supply.

Keep the firmware version, fixture and failed/skipped/unobserved cases with the result. Documented ratings are not measurements performed by this project.
