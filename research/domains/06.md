# OSIRIS · Forensic Science and Evidence Integrity

**Evidence:** Proposed domain research framework. The equations below are author-defined candidate models, not measured findings or requirements quoted from standards.

**Research focus:** Observation validity and intervals of event ordering.

## Governing model

```text
t_i in [observed_i-offset_bound_i, observed_i+offset_bound_i]
```

Infer A before B only when upper(A)<lower(B); overlapping intervals are indeterminate. A timeline order does not establish cause. Acquisition errors remain separate from clock errors.

**Competing models:** Sort timestamps directly; assume absent record means event absent.

**Required record schema:** Artifact digest, source, acquisition version, observation window, timestamp bound, chain-of-custody step, known fixture truth. Extend the schema with provenance digest, units, coverage window, collection permission, missingness reason and transformation revision. Use explicit null values for missing observations; do not turn missing into zero.

## Evaluation contract

Measure Ordering accuracy, indeterminate fraction, evidence reproducibility, traceable inference rate. Freeze a mission-specific primary endpoint and acceptable resource cost before tuning. Compare the candidate and baseline on the same scenario/partition. Include a no-intervention or null fixture to detect accidental leakage. Report uncertainty at the independent unit—scenario, channel, device or team—and analyze the worst-performing subgroup rather than relying on a portfolio average.

**Adverse cases:** Known clock offsets; partial acquisitions; duplicate records; missing log interval; parser version changes.

**Graduate challenges:** Unsynchronized clocks; duplicated events; destructive acquisition; unsupported negative inference. For each challenge, distinguish a limitation of the estimator from a limitation of available evidence. Ask whether the parameter is identifiable, whether the mechanism transfers to a new environment and which observation could distinguish rival explanations.

**Resource plan:** NIST CFReDS fixture selection; synthetic evidence first; read-only analysis with pinned tools. Before implementation, produce a concrete bill of materials, input size, memory/storage estimate, runtime bound and personnel-hours estimate. No universal cost or readiness claim is made here.

## Applicable data and its limits

[NIST Computer Forensic Reference Data Sets](https://cfreds.nist.gov/). Known-ground-truth acquisition/parser and inference evaluation. Pin fixture and documented truth; tool behavior on one fixture does not establish evidentiary validity in all cases. Resource budget: Fixture-specific storage and read-only tooling. Current status: portal resolved but text not retrievable; fixture contents unverified. Access/rights: Review each dataset terms; portal license is not automatically fixture license.
