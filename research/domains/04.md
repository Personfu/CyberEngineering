# VOYAGER · Supply Chain & Provenance

**Evidence:** Proposed domain research framework. The equations below are author-defined candidate models, not measured findings or requirements quoted from standards.

**Research focus:** Evidence freshness and transitive component dependence.

## Governing model

```text
E(a,t) = sum_j alpha_j I[e_j binds artifact a AND is current at t]
```

alpha_j are declared decision weights, not empirical trust probabilities. Keep authenticity, reproducibility, vulnerability relevance and maintainer continuity as separate axes.

**Competing models:** Flat component count; unsigned inventory; latest package name match.

**Required record schema:** Artifact digest, package ecosystem and version, dependency edge, builder identity, provenance predicate, evidence expiry. Extend the schema with provenance digest, units, coverage window, collection permission, missingness reason and transformation revision. Use explicit null values for missing observations; do not turn missing into zero.

## Evaluation contract

Measure Evidence completeness, false acceptance, reproducibility rate, remediation lead time. Freeze a mission-specific primary endpoint and acceptable resource cost before tuning. Compare the candidate and baseline on the same scenario/partition. Include a no-intervention or null fixture to detect accidental leakage. Report uncertainty at the independent unit—scenario, channel, device or team—and analyze the worst-performing subgroup rather than relying on a portfolio average.

**Adverse cases:** Stale SBOM; missing build link; renamed package; optional dependency; identical name in different ecosystems.

**Graduate challenges:** Namespace collisions; incomplete dependency graph; provenance verifier trust; version range ambiguity. For each challenge, distinguish a limitation of the estimator from a limitation of available evidence. Ask whether the parameter is identifiable, whether the mechanism transfers to a new environment and which observation could distinguish rival explanations.

**Resource plan:** SPDX/CycloneDX parser, provenance verifier and owned builds; public metadata snapshots. Before implementation, produce a concrete bill of materials, input size, memory/storage estimate, runtime bound and personnel-hours estimate. No universal cost or readiness claim is made here.

## Applicable data and its limits

[SLSA specification v1.2](https://slsa.dev/spec/v1.2/). Artifact identity, source/build provenance and freshness study. Evidence validity differs from software correctness; a claimed level requires all actual evidence requirements. Resource budget: Owned build artifacts, local verifier, snapshot statements. Current status: v1.2 primary specification inspected. Access/rights: Follow specification/documentation license and upstream verifier license.
