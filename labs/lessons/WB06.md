# WB06 · Read a local HTTP response

**Offline fixture · Network observability · Foundation**

Distinguish HTTP 200, HTTP 404 and a transport failure.

## Materials

Python local server and the harmless health fixture.

## Procedure

1. Start the loopback fixture server.
2. Request health.json and a missing path.
3. Stop your server and repeat to observe a connection error.

## Commands

Run from the repository root unless the walkthrough gives a different checkout/directory.

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory labs/fixtures
```

## Expected result

The full guide supplies second-terminal requests. Expect 200/404 while running, then connection failure after stopping.

## Failure cases and interpretation

Do not claim a 404 is a connection failure. The helper rejects external targets and redirects.

## Record

Keep the input/source version, command, relevant output and interpretation together. Label a fixture synthetic. Physical-device work needs the actual model, firmware and conditions. Do not report an unrun exercise as passed.
