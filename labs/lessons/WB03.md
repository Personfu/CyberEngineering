# WB03 · Refuse an invalid flash plan

**Offline fixture · Firmware · Foundation**

Demonstrate that metadata and example-only checks occur before any hardware action.

## Materials

Example-only manifest; a port string is an explicit plan input, not an opened device.

## Procedure

1. Read board/chip/kind/offset fields.
2. Run the example-only plan request.
3. Inspect the rejection and confirm that no command was executed.

## Commands

Run from the repository root unless the walkthrough gives a different checkout/directory.

```bash
python -m labtools.benchkit flash-plan labs/fixtures/example-manifest.json --board cardputer --port /dev/ttyACM0
```

## Expected result

Exit 1 explains that the example fixture cannot produce a board-write plan.

## Failure cases and interpretation

An app-only/OTA image, wrong board or wrong chip must not be silently accepted. Real plans remain dry runs.

## Record

Keep the input/source version, command, relevant output and interpretation together. Label a fixture synthetic. Physical-device work needs the actual model, firmware and conditions. Do not report an unrun exercise as passed.
