# WB21 · Model an update state machine

**Offline fixture · Formal assurance · Foundation**

Define transitions that exclude unverified or mismatched artifacts.

## Materials

Paper/state diagram and the helper validation tests.

## Procedure

1. Define known_good/downloaded/verified/staged/booted/recovered states.
2. Write invariants for staging and recovery.
3. Use parser/manifest negative cases as examples, not a proof of the whole bootloader.

## Commands

Run from the repository root unless the walkthrough gives a different checkout/directory.

```bash
python -m unittest discover -s tests -p test_benchkit.py -v
```

## Expected result

The software invariants are exercised; the physical bootloader remains a separate system.

## Failure cases and interpretation

A finite test suite is not exhaustive formal verification.

## Record

Keep the input/source version, command, relevant output and interpretation together. Label a fixture synthetic. Physical-device work needs the actual model, firmware and conditions. Do not report an unrun exercise as passed.
