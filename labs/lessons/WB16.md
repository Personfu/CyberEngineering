# WB16 · Write a harmless YARA rule

**Optional tool · Detection engineering · Applied**

Explain a match using authored marker text and a negative fixture.

## Materials

YARA CLI plus the original training rule/text.

## Procedure

1. Read the file-size and marker conditions.
2. Run the positive text fixture and negative health JSON.
3. Change the fixture and explain the result without assigning malware identity.

## Commands

Run from the repository root unless the walkthrough gives a different checkout/directory.

```bash
yara examples/yara/nightshift.yar examples/yara/training.txt
yara examples/yara/nightshift.yar labs/fixtures/health.json
```

## Expected result

Only the authored training text should match. Requires the optional YARA CLI.

## Failure cases and interpretation

A rule match proves its condition, not malware attribution; this is not a real malware dataset.

## Record

Keep the input/source version, command, relevant output and interpretation together. Label a fixture synthetic. Physical-device work needs the actual model, firmware and conditions. Do not report an unrun exercise as passed.
